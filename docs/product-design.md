# 产品设计文档：Resume-Star-Skill

> 在校生简历素材增强 Claude Code Skill

---

## 1. 产品定位

**产品名称：** Resume-Star-Skill（暂定）

**产品形态：** Claude Code Skill（一个 Skill，非多个）

**核心愿景：** 帮助在校生从自己的课程项目、实习项目中提取亮点，结合目标 JD 要求，生成可用的 STAR 格式简历描述。

**一句话描述：** 粘贴 JD + 指定本地项目路径 → 对话式生成 STAR 简历素材。

---

## 2. 用户画像

**目标用户：** 在校生（本科生、研究生）

**用户特征：**
- 有课程项目、实验室项目或短期实习经历，但不确定哪些值得写进简历
- Git 使用习惯参差不齐，仓库可能只有少量 commit
- 不了解 STAR 法则，不确定"怎么把做过的东西写得好"
- 对 JD 缺乏解读能力，不知道企业真正在找什么样的人

**核心痛点：**
1. **不知道自己有什么可写** —— 做了项目但提炼不出亮点
2. **不知道 JD 在找什么** —— 对岗位要求的理解停留在字面意思
3. **不知道怎么写好** —— 缺乏将技术经历转化为简历语言的能力

---

## 3. Skill 架构

**一个 Skill，三个阶段，对话贯穿。**

```
用户输入 JD 文本 + 本地项目路径
        │
        ▼
┌─────────────────┐
│  阶段 1: JD 解析  │  提取关键技能、能力权重、隐性要求
└────────┬────────┘
         │ JD 结构化数据
         ▼
┌─────────────────┐
│  阶段 2: 项目扫描  │  扫描目录结构、README、关键文件，提取项目亮点
└────────┬────────┘
         │ 项目亮点列表
         ▼
┌─────────────────┐
│  阶段 3: STAR 生成  │  基于 JD 要求 + 项目亮点，生成 STAR 描述
└─────────────────┘
         │
         ▼
  输出 2-3 条 STAR 格式简历描述
  用户对话微调 → 输出最终版本
```

### 阶段 1: JD 解析

**输入：** 用户粘贴的 JD 文本（或 JD 链接，Skill 尝试抓取）

**处理：**
- 提取硬技能关键词（语言、框架、工具）
- 提取软技能和隐性要求（团队协作、问题解决能力等）
- 评估各能力的权重（must-have vs nice-to-have）
- 识别企业/岗位风格（初创 vs 大厂、偏业务 vs 偏底层）

**输出：** 结构化的岗位画像摘要，向用户展示并确认

### 阶段 2: 项目扫描

**输入：** 用户提供的本地项目路径

**处理：**
- 扫描目录树结构，识别项目类型（前端/后端/全栈/数据/移动端）
- 读取 README、package.json / requirements.txt / pom.xml 等配置文件，提取技术栈
- 扫描关键源码文件，识别核心功能模块
- 检查 Git log（如有），了解开发历程和贡献范围

**Fallback：** 如果用户没有本地项目或项目过于简单，允许用户手动描述项目经历，Skill 仍可基于 JD 生成 STAR 框架

**输出：** 项目亮点列表（做了什么、用了什么技术、解决了什么问题），向用户展示并确认

### 阶段 3: STAR 生成

**输入：** 阶段 1 的岗位画像 + 阶段 2 的项目亮点

**处理：**
- 将项目亮点与 JD 要求做匹配，优先选择匹配度高的亮点
- 为每个亮点生成 STAR 格式描述（Situation-Task-Action-Result）
- 支持"技术向"和"业务向"两种表述风格
- 量化结果：尽量补充可量化的成果描述

**输出：** 2-3 条 STAR 格式的简历描述块（Markdown 格式），用户可对话微调

### 对话交互设计

对话贯穿三个阶段，每个阶段结束后都向用户展示中间结果并请求确认：

- 阶段 1 后：**"我分析了这份 JD，核心要求是 X、Y、Z，其中 X 最重要。这样理解对吗？"**
- 阶段 2 后：**"我从你的项目中发现这些亮点：A、B、C。你觉得哪个最值得展开？有没有我遗漏的？"**
- 阶段 3 后：**"这是基于你的项目和目标岗位生成的 3 条简历描述，你可以告诉我哪里需要调整。"**

用户可随时回退到上一阶段修改输入。

## 4. 技术方案

### 产品形态：Claude Code Skill

```
resume-star-skill/
├── skill.md          # Skill 定义（prompt、触发条件、流程描述）
```

Skill 直接运行在 Claude Code 环境中，可使用 Claude Code 的所有内置能力：
- 文件读取（Read、Glob）—— 扫描项目
- 目录探索（Bash）—— 运行 git log 等命令
- 网页抓取（WebFetch）—— 抓取 JD 链接内容
- 对话交互 —— 与用户确认和微调

### 技术栈

| 组件 | 选择 | 理由 |
|------|------|------|
| 运行环境 | Claude Code | 用户本地运行，无需部署 |
| 项目扫描 | Claude Code 内置工具（Read、Glob、Grep、Bash） | 无需额外依赖 |
| JD 获取 | 用户粘贴文本 / WebFetch 抓取链接 | 最小化实现 |
| 输出格式 | Markdown | 用户直接复制使用 |

### 关键技术决策

1. **不做 AST 解析。** 在校生项目以功能完整性为主，AST 级别的代码分析投入产出比低。目录结构 + 配置文件 + 关键文件扫描足以提取亮点。
2. **不做架构模式识别。** MVC/DDD 等模式识别对在校生简历价值低，且增加复杂度。
3. **不做自建对话 UI。** Skill 形态下，Claude Code 本身就是对话界面。
4. **支持无 Git 仓库的 fallback。** 允许用户手动描述项目经历，Skill 仍可完成 JD 解析 + STAR 生成。

## 5. MVP 功能范围

### 包含（MVP）

- [x] JD 文本解析（关键词提取、能力权重、岗位风格识别）
- [x] 本地项目扫描（目录结构、技术栈、核心功能识别）
- [x] STAR 简历描述生成（基于 JD + 项目亮点）
- [x] 对话式微调（用户可随时修改、补充、回退）
- [x] Markdown 输出
- [x] 无项目的 fallback（用户手动描述项目）

### 不包含（后续迭代）

- [ ] 浏览器插件形态
- [ ] 在线简历平台浮窗集成
- [ ] AST 级别代码分析
- [ ] 架构模式识别（MVC、DDD 等）
- [ ] Git commit 历史深度分析
- [ ] 多版本 STAR 生成对比
- [ ] 用户账户 / 数据持久化

---

## 6. 成功衡量指标

| 指标 | 定义 | MVP 目标 |
|------|------|---------|
| 内容采用率 | 用户最终采纳的 STAR 条数 / 生成总条数 | ≥ 60% |
| 生成效率 | 从输入 JD + 项目路径到第一条可用 STAR 的时间 | ≤ 5 分钟 |
| 单条迭代次数 | 一条 STAR 从生成到满意所需的对话交互次数 | ≤ 3 次 |
| 复用率 | 用户换一个 JD 后再次使用 Skill 的比例（定性观察） | 有复用行为 |
